# Подготовка релиза

1. Обнови `version.py`, `version_info.txt`, README и CHANGELOG. Для новой версии используй новую папку `release/<версия>`.
2. Создай `.venv` и установи `requirements.txt`, если окружение ещё не готово.
3. Выполни `./build.ps1` в PowerShell. Сценарий запускает тесты, собирает один EXE с Qt и лицензиями, проверяет его запуск и создаёт архивы.
4. Проверь `qa/build-check/report.json`, снимки обеих тем и содержимое архивов. `report.json` должен содержать `ok: true`, `frozen: true` и `window_controls: true`.
5. Запусти тесты из распакованного архива исходников и проверь запуск EXE в отдельной папке. Проверочный режим `--smoke-test <папка>` использует изолированные настройки.
6. Создай коммит и тег `v<версия>`, отправь их в `origin/main`.
7. Создай GitHub Release с названием `Kana Studio v<версия>`. Приложи `KanaStudio.exe`, `KanaStudio-win-x64.zip`, `KanaStudio-v<версия>-source.zip` и `SHA256SUMS.txt` из `release/<версия>`.

Исходники и снимки интерфейса хранятся в Git. `.venv`, временные проверки и готовые релизные файлы исключены через `.gitignore`.

Если существующий EXE запущен, собери выпуск в отдельную папку: `./build.ps1 -OutputDirectory "$env:TEMP\KanaStudio-release"`. В этом случае результаты проверки находятся в подпапке `verification` выбранного каталога.
